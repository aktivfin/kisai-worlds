# KisAI Worlds — 0.7 Extraction RPG Prototype

KisAI Worlds — голосовая AI extraction-RPG для партий от 1 до 5 игроков.

Главная идея: игрок выбирает активное событие на карте, берёт постоянного персонажа и ограниченный рюкзак, платит за вход / использует подписку, рискует персонажем и принесёнными вещами, а при успешной эвакуации получает XP и уникальный лут, который продолжает жить в общей экономике.

Полный канон механик: `GAMEPLAY_ECONOMY.md`.

## Игровой цикл

1. Открыть карту мира.
2. Выбрать одно из 3–9 активных событий.
3. Выбрать живого персонажа.
4. Собрать ограниченный рюкзак из безлимитного склада аккаунта.
5. Войти в приключение одному или группой до 5 игроков.
6. Говорить или писать действия.
7. AI GM интерпретирует намерение; сервер определяет DC, кидает d20 и применяет последствия.
8. Найти лут, материалы, редкие точки зачарования.
9. Завершить цели и эвакуироваться.
10. Вынести предметы на склад, использовать их в следующем походе или продать другому игроку.

## Карта событий

Каталог содержит 9 приключений.

Одновременно активно 3–9 событий. Ротация меняется каждые 6 часов.

У события фиксированы:
- danger tier;
- рекомендуемый размер группы;
- длительность;
- цена входа / бесплатный статус;
- XP;
- loot tier;
- точки мира;
- иногда кузница или алтарь зачарования.

Сложность **не масштабируется** под группу. Если один игрок идёт в событие, рассчитанное на пятерых, сервер не снижает DC.

За успешный underfilled-run повышается XP и количество гарантированного уникального лута.

## Персонажи

Базово у аккаунта 3 слота живых персонажей.

У персонажа есть:
- постоянный id;
- уровень и XP;
- навыки и способности;
- история походов;
- статус alive/dead.

Смерть окончательная. Погибший персонаж остаётся в истории, но выбрать его снова нельзя. Живой слот освобождается.

## Склад и рюкзак

Склад принадлежит аккаунту и не уничтожается при смерти.

В поход персонаж берёт только ограниченный набор вещей:
- база: 6 слотов;
- вместимость растёт с уровнем;
- максимум: 10.

Рискуют только вещи, которые реально были взяты в приключение.

Если персонаж погиб, содержимое его рюкзака остаётся в физической сцене. Живые союзники могут подобрать конкретные экземпляры и вынести их.

## Кубики и риск

LLM не решает числа.

AI GM предлагает:
- нужен ли check;
- какой навык релевантен;
- safe / risky / lethal;
- небольшую ситуационную поправку;
- narration;
- возможное перемещение по существующей геометрии.

Сервер:
- выбирает фиксированный DC события;
- кидает d20;
- применяет модификатор навыка/уровня;
- обрабатывает natural 1 / 20;
- начисляет раны;
- фиксирует смерть.

Клиент только анимирует уже определённый сервером результат.

## Лут

Экипировка — уникальные item instances, а не копии из общего списка.

На генерацию влияют:
- danger tier события;
- уровень и билд героя;
- доминирующие навыки;
- поведение игрока в конкретном приключении.

Сервер контролирует rarity/power-budget.

У предмета сохраняются:
- id;
- serial;
- provenance;
- origin character/build;
- enchantments;
- visual card.

Продажа или смена владельца не перегенерирует предмет.

## Крафт

Вне приключений можно крафтить только расходники:
- лечение;
- верёвки / traversal;
- побег;
- временные бонусы.

Рецепты и стоимость материалов детерминированы.

Оружие и броня через меню не крафтятся.

## Зачарование

Зачарование возможно только внутри подходящего события.

Нужно:
- принести уникальный предмет в рюкзаке;
- принести ингредиенты;
- физически добраться до кузницы/алтаря;
- пройти серверную проверку.

Каждый ингредиент имеет заранее известный тип эффекта. Качество результата зависит от tier кузницы и проверки.

Ингредиенты тратятся даже при провале.

## Рынок

На рынке продаются конкретные экземпляры оборудования.

Продавец сам задаёт цену в KAI.

Сохраняются serial, provenance и enchantments.

Комиссия прототипа: 2.5%.

KAI пока off-chain и не имеет cash-out.

## Монетизация прототипа

Архитектура поддерживает:
- бесплатные события;
- оплату отдельного похода для каждого участника;
- общую подписку;
- дополнительные слоты персонажей.

Реальный checkout-провайдер пока не подключён. В репозитории реализованы только серверные access/entitlement gates и данные продуктов.

## Voice / AI

При настроенных провайдерах:

`микрофон -> STT -> AI GM planner -> server dice/mechanics -> narration -> TTS`

Без LLM текстовый runtime продолжает работать через deterministic fallback.

## Запуск

Требуется Node.js 20+.

Windows:
`START_WINDOWS.bat`

Linux:
`./START_LINUX.sh`

LAN:
`START_LAN_WINDOWS.bat` или `./START_LAN_LINUX.sh`

По умолчанию:
`http://localhost:8787`

## Проверки

`npm run check`

`npm run validate:ui`

`npm run test:smoke`

`npm run validate:assets`

`npm run verify`

Source/runtime smoke проходит полный extraction-loop, включая permadeath и восстановление выпавшего уникального предмета союзником.

## Текущие ограничения

- комнаты пока in-memory;
- профили/рынок используют локальный JSON;
- billing provider ещё не подключён;
- continuous party voice ещё не реализован;
- полноценная быстрая генерация канонического кадра и personal POV ещё впереди;
- реальные JPG/MP3 ассеты должны быть добавлены отдельно.

См. `PROJECT_STATUS.md` и `ROADMAP.md`.
