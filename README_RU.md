# KisAI Worlds — Windows Demo 0.5

Voice-first multiplayer AI RPG prototype for Windows/LAN.

## Что изменилось в 0.2

- Полностью переработано главное меню под Steam-RPG вместо обычной web-панели.
- Добавлены сгенерированные игровые арты и отдельные визуальные слои для меню, лобби, конструктора героя и игровой сцены.
- Лобби теперь является полноценной сценой: фон таверны, карточки игроков, ready-state, приглашение, voice-status и кнопка старта.
- Конструктор персонажа встроен в лобби: концепция → AI-баланс → готовность.
- Сила героя автоматически ограничивается бюджетом текущего уровня, даже если игрок просит сверхсильную способность.
- Новый игровой HUD: партия слева, каноническая сцена по центру, GM narration, voice dock, кадры сцены и журнал событий.
- Плавные переходы между экранами, фоновые camera drift/parallax, микропульсация микрофона и анимация waveform во время записи.
- Улучшено состояние подключения и визуальная обратная связь во время STT → GM → TTS.
- Генерация AI-кадров по-прежнему опциональна и может быть выключена для дешёвого демо.

## Запуск на Windows

### Обычный локальный запуск
1. Установите Node.js 20+.
2. Распакуйте папку проекта.
3. Дважды нажмите `START_WINDOWS.bat`.
4. Откройте `http://localhost:8787`.

### Игра по локальной сети
1. Хост запускает `START_LAN_WINDOWS.bat`.
2. Разрешает Node.js в Windows Firewall, если появится запрос.
3. Другие игроки открывают IP компьютера хоста с портом `8787`, например `http://192.168.1.10:8787`.
4. Вводят код комнаты.

## Игровой цикл

1. Хост выбирает сценарий и создаёт лобби.
2. Игроки подключаются по коду.
3. Каждый описывает желаемого героя и внешность.
4. AI создаёт героя, сохраняя концепцию, но адаптируя навыки под уровень.
5. Во время своего хода игрок удерживает кнопку микрофона и говорит действие.
6. Запись настоящего голоса отправляется остальным участникам.
7. STT преобразует речь в текстовое действие.
8. AI Game Master разрешает действие с учётом мира, истории, персонажа и уровня.
9. Ответ GM озвучивается через TTS.
10. Через заданное число GM-ходов может генерироваться новый ключевой кадр сцены.

## AI Providers

Откройте `⚙ AI` внутри игры.

Поддержаны:
- LLM: OpenAI-compatible endpoint.
- STT: OpenAI-compatible transcription endpoint.
- TTS: OpenAI или ElevenLabs.
- Image: OpenAI-compatible image generation endpoint.

API-ключи сохраняются локально на машине хоста в `data/config.json`.

## Без API ключей

Игра остаётся запускаемой: используются fallback-персонажи и fallback-GM. Голосовое распознавание и синтез речи требуют настроенного провайдера.

## Что пока НЕ является финальной Steam-сборкой

Это браузерный Windows/LAN vertical slice, запускаемый локальным Node-сервером. Для полноценного Steam-релиза следующий технический слой — desktop shell/engine build, Steam Networking/WebRTC для постоянного voice-channel, аккаунты/сохранения, полноценный authoritative world state и персональные POV-кадры каждого игрока.

## Demo 0.3 — Adaptive Soundtrack

В игру встроены 14 пользовательских музыкальных треков. Музыка управляется не простым плейлистом, а состоянием сцены, которое AI Game Master возвращает вместе с narration. Допустимые состояния: `explore`, `tavern`, `investigation`, `discovery`, `tension`, `chase`, `ritual`, `abyss`, `dread`, `hell`, `boss`, `grief`.

Сопоставление:
- Main menu → The Unknown World
- Party lobby / подготовка → Candlelight over the Map
- Спокойное исследование / гавань → Rain at the Harbor
- Таверна / деревянные интерьеры → Wet Timber Pulse
- Расследование / неразрешённая тайна → Unresolved Minor
- Открытие / переход к новой тайне → The Threshold of Dorian
- Растущее напряжение / лёгкий бой → Phrygian Ostinato
- Погоня → Wet Street Pursuit
- Культ / ритуал → Hidden Ceremony
- Бездна / огромная глубина → The Vast Below
- Давящий страх / приближение неизвестного → The Unbottomed Well
- Ад / жар / катастрофическая тяжесть → The Furnace's Breath
- Вход босса / last stand → The Boss Approaches
- Потеря персонажа / aftermath → Grief Under Pressure

Клиент делает плавный crossfade между состояниями. Пока говорит реальный игрок или TTS-гейммастер, музыка автоматически duck-ится примерно до 28% текущей громкости и затем возвращается. Громкость музыки регулируется в настройках и сохраняется локально.

Если LLM недоступна, встроенный fallback-классификатор всё равно переключает базовые состояния по игровому событию, поэтому демо не зависит от API для проверки аудиологики.

## Demo 0.4 — экипировка, редкости, рынок и риск смерти

В 0.4 добавлен отдельный экономический слой игры.

### Интерфейс
- верхние вкладки: Игра / Герой / Инвентарь / Рынок / Кошелёк;
- постоянный KAI-баланс в верхней панели;
- отдельный экран экипировки;
- фильтры инвентаря;
- карточки редкости предметов;
- инспектор конкретного экземпляра с serial и provenance;
- вторичный рынок игроков;
- журнал операций кошелька;
- дневной индикатор фарма KAI.

### Редкости
Предметы имеют уровни Common / Uncommon / Rare / Epic / Relic / Mythic. Более высокая редкость увеличивает бюджет аффиксов. Босс и важные открытия повышают шанс получить верхние редкости. Сила предмета всё равно привязана к уровню персонажа, чтобы рынок не превращал ранние приключения в pay-to-win.

### KAI и рынок
KAI в этой демо-сборке — внутренний off-chain ledger без денежной стоимости и вывода. Игрок получает KAI за осмысленные игровые ходы, действует дневной лимит, а повтор одного и того же текста не приносит награду. На рынке владелец задаёт цену сам. Покупатель получает конкретный предмет с тем же serial, а продавец получает цену за вычетом комиссии 2.5%.

### Смерть и собственность
Смерть теперь имеет экономический риск:
1. персонаж помечается погибшим и исключается из очереди ходов;
2. весь принадлежащий ему переносимый инвентарь снимается с профиля;
3. активные рыночные лоты погибшего также автоматически снимаются с продажи;
4. все эти предметы становятся loot pile в текущей физической сцене;
5. любой живой участник партии может забрать предмет поштучно — после этого он переходит в его постоянный профиль;
6. если группа переходит в следующую сцену/локацию, весь неподобранный лут помечается `lost` и больше не возвращается в экономику.

Таким образом рынок торгует не абстрактными копиями предметов, а конкретными экземплярами. Предмет хранит serial и цепочку происхождения: находка → владелец → смерть/подбор → листинг → сделка.

### Важно про настоящую крипту
Архитектура intentionally разделяет игровой economy ledger и gameplay runtime. Для демо это позволяет тестировать экономику без реальных денег. Переход на on-chain токен потребует отдельно выбрать сеть, модель custody/non-custody, правила комиссий, антибот/антифарм, защиту от дюпов и юридическую модель для Steam/регионов.

## Demo 0.5 — уникальный адаптивный лут

Приключенческий лут больше не создаётся из общего случайного списка. Сначала сервер роллит редкость и допустимый power-budget, затем генератор смотрит на конкретного персонажа: его архетип, концепцию, текущий уровень, распределение навыков, способности и слабость. Из этого создаётся единичный экземпляр предмета.

LLM (если подключена) отвечает за название, лор, тип/слот, ситуационную пассивку, синергии и visual prompt для будущего изображения предмета. Сервер не доверяет модели численную силу: редкость, уровень и итоговые аффиксы валидируются и ограничиваются серверным бюджетом. Без LLM используется procedural fallback с той же логикой адаптации.

Каждый такой предмет хранит `adaptiveFor`: имя и архетип героя, уровень при создании, его доминирующие навыки и `buildFingerprint`. Это фиксируется только в момент рождения предмета. При смерти, подборе союзником, продаже или последующей перепродаже предмет НЕ перестраивается под нового владельца. Сохраняются тот же `item.id`, serial, статы, пассивка, лор и исходная специализация.

Пример: у следопыта с высокой Ловкостью и Восприятием выше вероятность получить оружие/инструмент с синергией под эти навыки; у силового стража — оружие/броню под Силу/Волю; у арканиста — charm/tool под Интеллект/Волю. Редкость определяет объём бонусов, а не направление билда.
